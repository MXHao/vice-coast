# R14 graphics controls and conservative CPU work

The title toolbar has a labeled **画质** entry; during play, pause and choose **画质设置**. All three modes switch immediately, keep native safe-area HUD, game and touch coordinates and use an isolated storage value `vice-coast-graphics-v1`. No automatic downgrade. Choosing 最高 restores the original render settings. An absent, invalid or unreadable preference means 最高; blocked storage writes still apply to this session. The modal uses the existing XA pause/Back/Escape flow.

| Mode | Backbuffer pixel ratio (b = original startup DPR capped at 2.5) | Directional sun shadow texture (s = native, hardware-capped up to 4096) |
|------|------|------|
| 最高 | b | s |
| 均衡 | min(1.5, 0.84b) | min(2048, s) |
| 流畅 | min(1, 0.68b) | min(1024, s) |

For b=2.5 and s=4096, a same-sized viewport draws approximately 36% / 16% as many primary pixel samples by *area* in balanced/smooth; shadow texel counts are 25% / 6.25% of high. This is workload sizing, **not measured FPS**. The pinned Three renderer reapplies its existing CSS size when its pixel ratio changes. The original shadow pass allocates its render target only when the old map is null or its shadow type changes; on an actual map-size change, release the light's owned targets, clear them, update the matching sunlight tracking/snap interval, and let the native shadow pass recreate them. No shadow cadence skipping, freezing, or stale cached textures. No reduced view distance, city/actor density, shape, pose rate, simulation frequency, lighting, AA, texture content, camera tuning, reflection, water shader, HUD or authored overlays in any mode. No per-frame polling for the user's preference.

The original walker loop repeats the same axis-aligned interval predicate across 275 urban blockers up to twice per walker/substep. In every preset a per-batch spatial index keeps original volume order and exact world/foot/driving inequalities. Padded 16-unit cells cover both fixed walker query radii (0.19/0.22). Validate the full array and every identity/bound at batch start: replacement, mutation, reordering, insertions and removals rebuild the index; unsupported shapes/sparse data and larger radii fall back. This is not used by drive contact, combat, story or the camera. There is no cross-frame player/actor pose or visibility cache.

In the compact 45-step 1/60s native-start fixture with all 25 walkers, bound-component reads were 770,940 vs 325,455, with the same walker transforms/phase at the end. The highest-preset digest of the compact native scene also matched R13: 2,929 ordered objects, 473 geometries, 299 materials. It covers transforms, geometry buffers, local material assignments and selected parameters, visibility, instances, shadow settings and camera projection; it is not a framebuffer comparison. This counts reads including the new validation, **not elapsed CPU milliseconds**, GPU load or target-device experience. Deliberately untouched: shadow traversal frequency and draw count, physical vehicle meshes, art instancing, native fog/culling, PMREM/cubemap capture, rig/AI update scheduling, full-screen/hidden-tab behavior, native camera angle and all story/save APIs. Without device profiling, there is no evidence to warrant approximating any of these.
